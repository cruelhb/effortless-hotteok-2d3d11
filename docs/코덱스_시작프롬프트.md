## 이 사이트가 무엇인가
**각 팀이 자기 팀 회식비가 얼마나 남았는지 간단히 조회하는 용도다. 그게 전부다.**
상세 데이터 관리는 관리자가 엑셀로 따로 하고 있고 **그 엑셀이 원본**이다.
그래서 사용 내역·지출 항목·참석자 명단 같은 **상세 입력 기능은 넣지 않는다.**
사이트에 또 입력하게 만들면 관리 지점이 둘로 늘어나 결국 어긋난다.

새 기능을 제안하기 전에 스스로 물을 것:
"이게 팀이 잔액을 확인하는 데 필요한가, 아니면 관리자가 엑셀로 이미 하는 일인가?"
후자면 만들지 말 것.

## 기술 구조
`index.html` **단일 파일**이 앱 전체다. 빌드 단계가 없다.
React 18 UMD + Babel Standalone(브라우저 내 JSX 컴파일) + Tailwind CDN +
Firebase compat SDK(익명 인증 + Firestore 실시간 구독).

**단일 파일 구조를 유지할 것. Vite/npm/번들러를 도입하지 말 것.** (사용자 결정)

화면 2개 — 팀 조회(팀 선택 → 4자리 비밀번호 → 잔여 회식비)와
지원부 관리(비밀번호 진입 후 인라인 편집, 드래그앤드롭 순서, 팀 추가/삭제, 월 마감).

계산식:
  잔여(합계) = 전월이월 + (인원 × 인당금액) + (추가인원 × 추가인당금액) − 당월사용
  면담비(별도) = 총원 0명 → 0 / 1~10명 → 50,000 / 11명~ → 100,000

잔여 계산은 `calcTeamBalance()` 한 곳에만 있다. **식을 화면마다 복사하지 말 것.**
예전에 따로 적혀 있어서 한쪽만 고치면 조용히 어긋나는 문제가 있었고 통합한 것이다.

## 반드시 지켜야 할 함정 5가지 (모두 실제로 겪은 것)

### 1. 커밋 작성자를 바꾸지 말 것
비공개 저장소 + Netlify 무료 플랜은 **인식된 기여자 1명만** 빌드를 허용한다.
저장소 로컬 config에 `cruelhb <142663431+cruelhb@users.noreply.github.com>` 로 설정돼 있다.
다른 이름/이메일로 커밋하면 **push는 성공하지만 Netlify가 빌드를 시작조차 하지 않는다.**
배포 목록에 실패 항목도 안 뜨고 조용히 무시되므로 알아채기 어렵다.

배포가 안 되는 것 같으면 가장 먼저 이것을 확인:
    git log -1 --format="%an <%ae>"

### 2. `/** @jsxRuntime classic */` 프래그마를 지우지 말 것
`<script type="text/babel">` 첫 줄에 있다. 지우면 Babel이 automatic 런타임으로 변환해
`react/jsx-runtime` 을 찾는데 UMD 빌드엔 그 모듈이 없어 **앱이 통째로 렌더링되지 않는다.**
Babel 버전도 운영본과 같은 7.24.0으로 고정되어 있다.

### 3. 로컬 테스트가 운영 Firestore에 붙는다
`run.bat` 으로 띄우면 **실제 운영 DB**에 연결된다. 값을 수정하면 팀원 화면에 즉시 반영된다.
안전하게 테스트하려면 `firebaseConfig.apiKey` 를 `null` 로 바꾼 **사본**을 만들어 띄울 것.
그러면 `isFirebaseConfigured` 가 false가 되어 localStorage 목업 모드로 동작한다.

### 4. 저장소 루트가 공개 배포된다 — 문서는 반드시 `docs/` 에
빌드 명령이 없어 `index.html` 외의 파일도 전부 URL로 열린다.
`_redirects` 로 막아 두었고 `/docs/*` 규칙이 있으니 **새 문서는 `docs/` 아래에 만들 것.**
루트에 새 파일을 추가한다면 `_redirects` 에 규칙을 넣고 **배포 후 `curl` 로 404 확인**할 것.

`_redirects` 를 고칠 때:
- **상태코드 뒤에 `!` (force)가 없으면 아무 효과가 없다.** Netlify는 실제 파일이 있는
  경로에서 파일을 우선하고 규칙을 무시한다.
- **한글 등 비ASCII 파일명은 경로 매칭이 안 되고, `/*.md` 같은 글로브도 지원되지 않는다.**
  (`*` 는 후행 splat 전용) 그래서 `docs/` 로 모으는 방식을 쓴다.

### 5. PowerShell 스크립트는 UTF-8 BOM이 필수
PowerShell 5.1은 BOM 없는 `.ps1` 을 ANSI로 읽어 한글이 깨지고, 파싱 에러로 아예 실행되지 않는다.
`backup.ps1`, `serve.ps1` 수정 시 BOM을 유지할 것.

## Firestore 쓰기 구조 — 건드릴 때 주의
- 관리 화면 입력은 **항목별 600ms 디바운스** 후 저장된다 (`handleUpdateTeam`).
- 저장 대기 중인 항목은 `pendingEditsRef` 로 보호해, 실시간 스냅샷이 입력값을 덮어쓰지 못하게 한다.
  **이 보호가 영구히 풀리지 않으면 그 팀 화면이 멈춘다.** 수정 시 반드시 해제 경로를 확인할 것.
- 월 마감은 `flushPendingWrites(['carryOver','usedAmount'])` 로 해당 항목 대기분을 버린다.
  버리지 않으면 뒤늦게 저장되어 마감 결과를 되돌린다.
- Firestore 구독 `useEffect` 의존성은 `[user]` 다. **`[]` 로 바꾸지 말 것.**
  익명 로그인 완료를 기다리지 않으면, 규칙에 인증 요구가 들어가는 순간 첫 요청이 거절되고
  Firestore 리스너는 오류 시 끊긴 뒤 재시도하지 않아 전 사용자 화면이 빈 채로 멈춘다.

## 데이터 백업
`백업받기.bat` 더블클릭 → `backups\` 에 시각이 붙은 JSON(복원용) + CSV(엑셀용, BOM 포함) 저장.
`backups\` 는 조회 비밀번호가 포함되어 **git에 올라가지 않는다**(.gitignore). 외부 공유 금지.

**월 마감을 실행하기 전에는 반드시 백업할 것. 되돌리기 기능이 없고 백업이 유일한 복구 수단이다.**

주의: `backup.ps1` 의 값 변환 함수는 integer/string/double/boolean만 처리하고
나머지 타입은 `null` 로 버린다. 현재 데이터는 integer+string뿐이라 무손실이지만,
**배열(`arrayValue`)이나 객체(`mapValue`) 필드를 새로 추가하면 백업에서 조용히 빠진다.**
그런 필드를 추가한다면 `backup.ps1` 을 함께 고칠 것.
