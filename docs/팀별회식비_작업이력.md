## 시작하기 전에 (매 세션 필독)

### 이 사이트의 목적과 범위 (기능 제안 전 반드시 읽을 것)

**각 팀이 자기 팀 회식비가 얼마나 남았는지 간단히 조회해 보는 용도다. 그게 전부다.**

상세한 데이터 관리는 **관리자가 엑셀로 따로 하고 있고, 그 엑셀이 원본(source of truth)이다.**
엑셀은 관리자만 가지고 있다. 이 사이트는 그 결과 숫자를 팀에게 보여주는 창구일 뿐이다.

따라서 **상세 입력 기능은 넣지 않는다.** 사용 내역, 지출 항목, 참석자 명단 같은 것을
사이트에 입력하게 만들면 엑셀과 사이트 두 곳을 관리해야 하고 결국 어긋난다.

새 기능이 떠오르면 먼저 물을 것: *"이게 팀이 잔액을 확인하는 데 필요한가,
아니면 관리자가 엑셀로 이미 하고 있는 일인가?"* 후자면 만들지 말 것.
(2026-08-31에 사용 내역 기록 기능을 제안했다가 이 이유로 접었다. 아래 "접은 제안" 참고)

### 환경상 반드시 알아야 할 함정

1. **커밋 작성자를 바꾸지 말 것.**
   비공개 저장소 + Netlify 무료 플랜은 **인식된 기여자 1명만** 빌드를 허용한다.
   저장소 로컬 config에 `cruelhb <142663431+cruelhb@users.noreply.github.com>` 로 설정해 두었다.
   다른 이름/이메일로 커밋하면 **push는 성공하지만 Netlify가 빌드를 아예 시작하지 않는다.**
   배포 목록에 실패 항목조차 안 뜨고 조용히 무시되므로 알아채기 어렵다. (2026-08-31에 실제로 겪음)

2. **`/** @jsxRuntime classic */` 프래그마를 지우지 말 것.**
   `<script type="text/babel">` 첫 줄에 있다. Babel이 JSX를 automatic 런타임으로 변환하면
   `react/jsx-runtime` 을 찾는데 UMD 빌드에는 그 모듈이 없어 **앱이 통째로 렌더링되지 않는다.**

3. **로컬 테스트 시 운영 Firestore에 연결된다.**
   `run.bat` 으로 띄우면 실제 운영 DB에 붙는다. 값을 수정하면 팀원 화면에 즉시 반영된다.
   안전하게 테스트하려면 `firebaseConfig.apiKey` 를 `null` 로 바꾼 **사본**을 만들어 띄울 것.
   그러면 `isFirebaseConfigured` 가 false가 되어 localStorage 목업 모드로 동작한다.

4. **PowerShell 스크립트는 UTF-8 BOM이 필수.**
   PowerShell 5.1은 BOM 없는 `.ps1` 을 ANSI로 읽어 한글이 깨진다.
   BOM 없이 저장하면 파싱 에러로 아예 실행되지 않는다.

5. **저장소 루트가 공개 배포된다. 문서는 반드시 `docs/` 에 넣을 것.**
   빌드 명령이 없어 `index.html` 이외의 파일도 전부 URL로 열린다.
   `_redirects` 로 막아 두었고, `/docs/*` 규칙이 있으므로 **문서를 `docs/` 아래에 만들면
   규칙을 손댈 필요가 없다.** 루트에 새 파일을 추가한다면 `_redirects` 에 규칙을 넣을 것.

   `_redirects` 를 고칠 때 반드시 알아야 할 두 가지 (둘 다 실제로 겪음):
   - **상태코드 뒤에 `!` (force)가 없으면 아무 효과가 없다.**
     Netlify는 실제 파일이 존재하는 경로에서 파일을 우선하고 규칙을 무시한다.
   - **한글 등 비ASCII 파일명은 경로 매칭이 안 된다.** 또 `/*.md` 같은 일반 글로브도
     지원하지 않는다(`*` 는 후행 splat 전용). 그래서 `docs/` 로 모으는 방식을 쓴다.

   검증은 반드시 배포 후 `curl` 로 할 것. 404가 떠야 정상이다.
   참고로 `.gitignore` 는 규칙과 무관하게 404인데, Netlify가 점으로 시작하는 파일을
   애초에 배포하지 않기 때문이다. 이걸 규칙이 동작하는 증거로 오해하지 말 것.

## 2026-08-31 (1차 세션)

이전에 다른 AI로 만들어 이미 배포·운영 중인 사이트를 클로드 코드로 이어받는 첫 세션.
사용자 요청: 첨부한 `index.html` 을 분석하고 제안 + 필요한 정보 질의.

### 파악한 구조

단일 HTML 파일. React 18 UMD + Babel Standalone(브라우저 내 JSX 컴파일) + Tailwind CDN +
Firebase compat SDK(익명 인증 + Firestore 실시간 구독). 빌드 단계 없음.

화면 2개 — **팀 조회**(팀 선택 → 4자리 비밀번호 → 잔여 회식비)와
**지원부 관리**(비밀번호 진입 후 인라인 편집, 드래그앤드롭 순서, 팀 추가/삭제).

```
잔여(합계) = 전월이월 + (인원 × 인당금액) + (추가인원 × 추가인당금액) − 당월사용
면담비(별도) = 총원 0명 → 0 / 1~10명 → 50,000 / 11명~ → 100,000
```

### 사용자가 정한 방향

- 단일 파일 유지 + 경량화 (Vite 등 빌드 도입은 하지 않음)
- 작업 폴더를 위 경로로 옮기고 git으로 관리

운영 중인 파일을 먼저 그대로 커밋해 되돌릴 지점을 만듦.

**2. 안정성 5종 개선** (`5681924`)

| 문제 | 처리 |
|---|---|
| `onChange` 마다 Firestore 쓰기 | 항목별 600ms 디바운스. 10글자 입력 시 쓰기 10회 → **1회** 실측 |
| 동시 편집 시 입력값이 튐 | `pendingEditsRef` 로 저장 대기 중인 항목만 스냅샷 덮어쓰기 차단 |
| 팀 전멸 시 샘플 3팀 부활 | `snapshot.empty` 자동 생성 로직 제거 |
| 존재하지 않는 Tailwind 클래스 35곳 | `slate-550/555/450/455/350/850/750`, `p-4.5` 등. 무효라 스타일이 무시되고 있었음 |
| `document.execCommand('copy')` | `navigator.clipboard` + 비보안 컨텍스트 폴백 |

부수적으로 React 개발 빌드 → 프로덕션 빌드 (약 1.2MB → 142KB), `substr` → `crypto.randomUUID`.

디바운스 보호가 **영구히 풀리지 않으면 그 팀이 멈추므로** 3단계로 검증했다:
입력 중 외부 변경 도착 → 내 값 유지 / 동시에 다른 팀 → 정상 동기화 / 저장 완료 후 → 보호 해제되어 다시 동기화.

**3. 인증 순서 수정** (`752b613`) — 규칙 강화의 선행 조건
Firestore 구독 `useEffect` 의존성이 `[]` 라 **익명 로그인 완료를 기다리지 않았다.**
규칙이 다 열려 있어 지금은 무해하지만, 규칙에 인증 요구를 넣는 순간 첫 요청이 거절되고
**Firestore 리스너는 오류 시 끊긴 뒤 재시도하지 않아** 전 사용자 화면이 빈 채로 멈춘다.
의존성을 `[user]` 로 바꾸고, 인증 실패 시 로딩 화면에 갇히지 않도록 안내 화면을 추가했다.

**4. Firestore 보안 규칙 조사 + 초안** (`8598c3c`)

사용자가 콘솔에서 확인해 준 당시 규칙은 `match /{document=**}` 에 `allow read, write: if true`.
실제로 확인해 보니 **인증 토큰 없이 HTTP 200, 팀 49개 전량 조회됨**(읽기만 시도).
조회 비밀번호까지 전부 노출. 쓰기·삭제도 동일하게 열려 있어 **외부에서 명령 한 줄로 전체 삭제 가능**한 상태.

> 참고: 처음에 "규칙 만료로 사이트가 멈출 수 있다"고 경고했는데 **오판이었다.**
> `if true` 에는 날짜 조건이 없어 만료되지 않는다.

규칙 초안 작성 시 실제 데이터를 먼저 조사한 게 중요했다. 필드가 문서마다 다르다:
```
name, carryOver, usedAmount, memberCount, perPersonAmount, viewPasscode, order, createdAt  →  49/49
additionalMemberCount, additionalPerPersonAmount                                            →   4/49
id                                                                                          →   3/49
```
흔한 "필수 필드" 방식으로 검증을 쓰면 **45개 팀이 저장 불가로 잠긴다.** "있을 때만 검사"로 작성함.

**사용자 결정: 규칙은 바꾸지 않음.** 대신 정기 백업으로 대응하기로 함.

**5. 운영본과의 차이 발견** (`3f27f83`) — 하마터면 사이트를 깰 뻔한 건

Netlify 배포일이 6/19인데 작업 기준으로 삼은 파일은 6/9자였다. 저장소 원본을 받아 대조하니
실제 내용 차이가 2개 있었다: Babel 7.24.0 고정, **`@jsxRuntime classic` 프래그마**.
후자가 없으면 앱이 통째로 안 뜬다. 두 변경을 반영하고 Babel도 운영본과 같은 7.24.0으로 되돌렸다.

> 시도했다가 접은 방법: 내 변경분을 패치로 뽑아 운영본에 적용하려 했으나

> **반대 방향**(검증 끝난 내 파일에 운영본의 2가지 변경을 얹기)으로 전환했다.

**9. 월 마감 기능** (`4456d3b`)

사용자 확인 규칙: 합계 → 전월이월금액, 당월사용금액 → 0,
인원·인당금액·**추가인원 모두 유지**, 마이너스 잔액도 그대로 이월.
안전장치 수준은 "확인창만 간단히"로 요청받음.

되돌리기가 없으므로 **중복 마감 경고만은 확인창 안에 한 줄로 넣었다.**
두 번 실행하면 지원금이 두 번 얹히는데 화면상 조용히 넘어가기 때문. 팀 문서에 `lastClosedMonth` 를 남겨 판단한다.

함께 정리한 것 — 셋 다 마감 결과를 조용히 망가뜨릴 수 있었던 것들:
- 잔여 계산식이 관리/조회 화면에 **따로 적혀 있었다.** `calcTeamBalance()` 하나로 합침
- 디바운스 대기 중이던 `carryOver`/`usedAmount` 가 마감 후 저장되어 결과를 되돌리는 문제 →
  `flushPendingWrites(skipFields)` 로 해당 항목은 대기 상태를 버림
- `pagehide` 리스너가 이벤트 객체를 `skipFields` 인자로 넘겨 TypeError가 날 상황 → 감싸서 등록
- `firestore.rules` 에 `lastClosedMonth`/`lastClosedAt` 허용 추가 (빠뜨리면 규칙 적용 시 마감 차단)

검증(Firebase 끈 사본, 운영 데이터 무영향):

| 팀 | 마감 전 | 마감 후 |
|---|---|---|
| 일반팀 | 이월 100,000 / 사용 30,000 | 이월 **370,000** / 사용 0 |
| 마이너스팀 | 이월 0 / 사용 500,000 | 이월 **−350,000** / 사용 0 |
| 추가인원팀 | 이월 50,000 / 사용 0 | 이월 **450,000** / 사용 0 (추가 2명 유지) |

재실행 시 경고 표시 및 이월 합계 470,000 → 1,320,000 표시까지 확인. 조회 화면도 동일 계산으로 일치.

> **운영 사이트에서는 확인창을 열어보지 못했다.** 자동 승인 정책이 해당 클릭을 차단했고
> 우회하지 않았다. 운영에서는 버튼 존재·페이지 정상·콘솔 에러 없음까지만 확인했다.
> **즉, 실제 49개 팀 대상 마감은 아직 한 번도 실행된 적이 없다.**

**10. 공개 배포 파일 차단** (`4c62479` → `94a3c07` → `7298789`)

저장소 루트가 그대로 공개 배포되는 탓에 `firestore.rules`, `backup.ps1`, `serve.ps1`, `run.bat` 이

`_redirects` 로 막는 과정에서 두 번 틀렸고, 둘 다 배포 후 `curl` 검증으로 잡았다:

1. **`!` (force) 누락** — 첫 배포 후에도 네 파일 모두 그대로 200이었다.
   Netlify는 실제 파일이 있는 경로에서 파일을 우선하고 규칙을 무시한다.
   이때 `.gitignore` 만 404로 나와 규칙이 동작하는 것처럼 보였는데,
   그건 Netlify가 점 파일을 애초에 배포하지 않기 때문이었다. 헷갈리기 쉬운 지점.
2. **한글 파일명 매칭 실패** — `!` 를 붙인 뒤에도 작업이력 문서만 계속 200이었다.
   비ASCII 경로가 매칭되지 않았고, `/*.md` 같은 글로브도 지원되지 않는다.
   결국 문서를 `docs/` 로 옮기고 후행 splat `/docs/*` 로 해결했다.

최종 확인: 대상 5개 모두 404, `/` 와 `/?mode=user` 는 200, 앱 코드 정상 포함.

## 2026-10-12 — 관리자 당월사용금액 미입력/확정 0원 구분
