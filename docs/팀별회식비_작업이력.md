### 환경상 반드시 알아야 할 함정

1. **커밋 작성자를 바꾸지 말 것.**
   비공개 저장소 + Netlify 무료 플랜은 **인식된 기여자 1명만** 빌드를 허용한다.
   저장소 로컬 config에 `cruelhb <142663431+cruelhb@users.noreply.github.com>` 로 설정해 두었다.
   다른 이름/이메일로 커밋하면 **push는 성공하지만 Netlify가 빌드를 아예 시작하지 않는다.**
   배포 목록에 실패 항목조차 안 뜨고 조용히 무시되므로 알아채기 어렵다. (2026-08-31에 실제로 겪음)

2. **`/** @jsxRuntime classic */` 프래그마를 지우지 말 것.**
   `<script type="text/babel">` 첫 줄에 있다. Babel이 JSX를 automatic 런타임으로 변환하면
   `react/jsx-runtime` 을 찾는데 UMD 빌드에는 그 모듈이 없어 **앱이 통째로 렌더링되지 않는다.**

3. **로컬 테스트 시 운영 Firestore에 연결된다.**
   `run.bat` 으로 띄우면 실제 운영 DB에 붙는다. 값을 수정하면 팀원 화면에 즉시 반영된다.
   안전하게 테스트하려면 `firebaseConfig.apiKey` 를 `null` 로 바꾼 **사본**을 만들어 띄울 것.
   그러면 `isFirebaseConfigured` 가 false가 되어 localStorage 목업 모드로 동작한다.

4. **PowerShell 스크립트는 UTF-8 BOM이 필수.**
   PowerShell 5.1은 BOM 없는 `.ps1` 을 ANSI로 읽어 한글이 깨진다.
   BOM 없이 저장하면 파싱 에러로 아예 실행되지 않는다.

5. **저장소 루트가 공개 배포된다. 문서는 반드시 `docs/` 에 넣을 것.**
   빌드 명령이 없어 `index.html` 이외의 파일도 전부 URL로 열린다.
   `_redirects` 로 막아 두었고, `/docs/*` 규칙이 있으므로 **문서를 `docs/` 아래에 만들면
   규칙을 손댈 필요가 없다.** 루트에 새 파일을 추가한다면 `_redirects` 에 규칙을 넣을 것.

   `_redirects` 를 고칠 때 반드시 알아야 할 두 가지 (둘 다 실제로 겪음):
   - **상태코드 뒤에 `!` (force)가 없으면 아무 효과가 없다.**
     Netlify는 실제 파일이 존재하는 경로에서 파일을 우선하고 규칙을 무시한다.
   - **한글 등 비ASCII 파일명은 경로 매칭이 안 된다.** 또 `/*.md` 같은 일반 글로브도
     지원하지 않는다(`*` 는 후행 splat 전용). 그래서 `docs/` 로 모으는 방식을 쓴다.

   검증은 반드시 배포 후 `curl` 로 할 것. 404가 떠야 정상이다.
   참고로 `.gitignore` 는 규칙과 무관하게 404인데, Netlify가 점으로 시작하는 파일을
   애초에 배포하지 않기 때문이다. 이걸 규칙이 동작하는 증거로 오해하지 말 것.

> 참고: 처음에 "규칙 만료로 사이트가 멈출 수 있다"고 경고했는데 **오판이었다.**
> `if true` 에는 날짜 조건이 없어 만료되지 않는다.

규칙 초안 작성 시 실제 데이터를 먼저 조사한 게 중요했다. 필드가 문서마다 다르다:

**10. 공개 배포 파일 차단** (`4c62479` → `94a3c07` → `7298789`)

저장소 루트가 그대로 공개 배포되는 탓에 `firestore.rules`, `backup.ps1`, `serve.ps1`, `run.bat` 이
모두 HTTP 200으로 열리는 것을 확인했다. 특히 `firestore.rules` 주석에 보안 취약 상태가
그대로 적혀 있어 사실상 공개된 공격 안내문이었다 — **커밋 시 놓친 부분.**
주석을 중립적으로 고치고 상세 경위는 이 문서로 옮겼다.

`_redirects` 로 막는 과정에서 두 번 틀렸고, 둘 다 배포 후 `curl` 검증으로 잡았다:

1. **`!` (force) 누락** — 첫 배포 후에도 네 파일 모두 그대로 200이었다.
   Netlify는 실제 파일이 있는 경로에서 파일을 우선하고 규칙을 무시한다.
   이때 `.gitignore` 만 404로 나와 규칙이 동작하는 것처럼 보였는데,
   그건 Netlify가 점 파일을 애초에 배포하지 않기 때문이었다. 헷갈리기 쉬운 지점.
2. **한글 파일명 매칭 실패** — `!` 를 붙인 뒤에도 작업이력 문서만 계속 200이었다.
   비ASCII 경로가 매칭되지 않았고, `/*.md` 같은 글로브도 지원되지 않는다.
   결국 문서를 `docs/` 로 옮기고 후행 splat `/docs/*` 로 해결했다.

최종 확인: 대상 5개 모두 404, `/` 와 `/?mode=user` 는 200, 앱 코드 정상 포함.

- **Firestore 보안 규칙은 여전히 `allow read, write: if true`** (사용자 결정에 따라 미적용).

  `firestore.rules` 에 적용 가능한 제안본이 준비되어 있고, 선행 조건인 인증 순서 수정은 이미 배포됨.
  적용 순서는 **코드 배포 → 규칙 교체** 이며 코드는 이미 나가 있으므로 규칙만 바꾸면 된다.
